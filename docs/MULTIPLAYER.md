# Multiplayer development slice / 联机开发预览

The first usable AmberL version must include multiplayer (user decision, 2026-11-13).
This build implements a real Windows x64 vertical slice, not completion of Stage D.

## Host and join / 房主与加入者

1. Open **联机 → 创建服务端**, load the official version list, choose a release,
   name and port, read the Minecraft EULA and explicitly accept it. This creates a
   new Vanilla, Fabric, Quilt, modern Forge/NeoForge or Paper server under AmberL's own
   `servers/<id>` directory. Loader installation also needs compatible Java. No world is imported.
2. In **服务端**, refresh/select that server, explicitly choose compatible `java.exe`
   and memory, then start. **控制台** shows bounded output and accepts single-line
   commands. **保存并停止** sends `stop` and waits; it never kills all Java processes.
3. In **邀请房间**, download the verified networking component, choose the local
   Minecraft port and relay endpoint, then create a room. The default endpoint is
   `tcp://public.easytier.top:11010`; availability is not guaranteed. Copy the entire
   displayed invitation to a trusted friend. It contains a room secret, expires in
   24 hours and is not an account credential. Closing the room ends this host session.
4. On the friend's AmberL, download the same component. In **加入游戏**, paste the
   invitation, choose an unused local port and connect. Fill the room address, query
   Minecraft status, then launch the selected compatible game/account/Java. Newer
   versions with Quick Play can join automatically; older versions need normal
   game launch followed by entering the shown address in Minecraft's multiplayer UI.
5. A direct server address can also be queried/launched without an invitation.
   Room forwarding can target an existing locally running Minecraft server or an
   explicitly opened LAN world, but does not modify their files or start them.

服务端、房间与游戏有独立生命周期；退出房间不会自动停服，停止游戏不会自动结束房间。
退出 AmberL 会请求结束自己的任务、正常停服并等待保存；无响应进程仍可能让退出等待。
进程启动、服务端报告就绪、协议查询可响应、真实玩家入服是不同状态，界面分别说明。
房间邀请当前是 **AmberL 专用格式**，不能直接交换 AMBER 的邀请。

New servers bind **127.0.0.1**, require official account authentication, disable RCON
and query, and allow eight players. An empty player whitelist is explicitly disabled
at creation so authenticated invited players can enter. Anyone given the invitation
can attempt to join; a player allowlist can be managed using Minecraft console commands.
This is a room-code access model, not a player approval UI or a public server listing.

## Data and networking boundaries / 数据与网络边界

- Registry, cache, new worlds and downloaded components belong to the separate app
  directory. Server selection uses a saved directory identity; replaced directories,
  reparse paths and pre-existing hardlinked content are rejected before launch.
- Official server JAR size/hash is verified against catalog metadata before creation
  and startup. Existing destinations and damaged registries are preserved.
- EasyTier **2.6.4** is downloaded on explicit request from its pinned official release.
  ZIP, executable and required DLL hashes are checked. It runs with `--no-tun`, local
  RPC/guest-forward listeners and a host TCP whitelist for the selected game port.
  AmberL does not install a virtual adapter or change firewall/DNS/security settings.
  Windows may ask the user for network permission; the user handles that OS prompt.
- Room secrets are generated by Windows, passed in the child environment and excluded
  from process arguments, ordinary output and persistent configuration. Sharing an
  invitation intentionally shares that secret; do not put invitations in issue logs.
- The public relay is third-party infrastructure. Connections begin only when the user
  starts/joins a room. This build does not promise connectivity through every NAT.
- Per-game Java, account ID and memory preferences now persist in `launch-preferences-v1.json`.
  It contains no access/refresh tokens; those remain in the independent DPAPI store.
  Save explicitly in configuration, or launch/switch games to save the current choice.

## Evidence and remaining gates / 验证与剩余门槛

The developer fixture `cargo run --example multiplayer_smoke -- APP JAVA VERSION
--accept-eula [AUTH_APP GAME OS]` creates an isolated world, checks the official
component, starts a local relay and two separate room peers, queries the actual
Minecraft protocol, optionally joins with the already authorized test account, and
normally closes the game and server. It then reloads the same registered world and
stops again. It never imports accounts or uses the user's original worlds.

Actual Windows 11 / Java 25 / Vanilla 26.3 testing verified authenticated client
entry through two local room peers, normal client exit, graceful server exit and
world saving, followed by reloading and stopping that same world. Exact delivery
evidence is recorded in the PR and validation record.
**Two peers on one PC are not two physical devices.** Public-relay/NAT behavior,
two-computer gameplay and disconnect/reconnect acceptance remain open.

Minecraft 26.3 servers with Fabric 0.19.5, Quilt 0.31.0-beta.1, Forge 26.3-66.1.8
and NeoForge 26.3.0.103 have additionally passed actual readiness, query, console,
save and reload checks. Vanilla 1.12.2 with downloaded Java 8 and Forge 26.3 with
downloaded Java 25 also passed verified snapshot/new-copy restoration and startup.

**服务端配置** edits description, player limit, view distance, difficulty and mode
only while stopped. It detects stale edits and preserves unknown properties. A
durable recovery record blocks launch after interrupted writes until recovery; the
interrupted bytes are retained too. Chinese descriptions use Java property escapes.
The listener and authentication boundaries above remain enforced at startup.

**备份恢复** snapshots stopped app-owned servers. Restoration verifies every saved
file and creates a separate server; it never replaces the source world. Recoverable
removal hides the server while retaining its data and identity. **管理模组与插件**
uses the owned-content workflow described in CONTENT.md; it is not mod synchronization.

Paper uses stable builds from the official Fill catalog with exact URL/size/SHA-256
validation. Paper 26.3 build 249 with LuckPerms 5.5.71 passed actual startup/query,
plugin loading, graceful save, same-world restart and verified new-copy restoration.
Paper and plugins may download their own runtime libraries during first start.
AmberL pins the selected Paper entry JAR; it does not claim to sandbox third-party
Java code or independently validate every runtime download by that code. Restored
plugin files/configuration are preserved; content installation-group records are
not cloned to the new server and those restored files are treated as unmanaged.

**FRP** now provides an independent verified frpc process, protected saved token,
mandatory TLS CA verification and reconnection. See [FRP setup and evidence](FRP.md).

Public-node/two-device acceptance, a full player management
UI, translation/accessibility acceptance and clean-machine deployment remain open.
No stable release or merge is authorized by this preview.
